# راهنمای اجرای آزمایش‌های معتبر در Kaggle

فایل `kaggle_validated_experiments.py` به شش سلول مستقل با نشانگرهای
`# %%` تقسیم شده است. هر بلوک را در یک Code Cell جداگانه قرار دهید و در یک
Session تازه، از سلول ۱ تا ۶ به‌ترتیب اجرا کنید.

## ورودی‌های لازم

این دو Dataset را با گزینه Add Input به Notebook اضافه کنید:

1. `rodrigorosasilva/cic-ddos2019-30gb-full-dataset-csv-files`
2. `dhoogla/cicbotiot`

داده دوم یک نسخه منتشرشده و ثالث از Bot-IoT با ویژگی‌های CICFlowMeter است.
بنابراین در مقاله نباید ادعا شود که نویسندگان PCAPهای اصلی را شخصاً با
CICFlowMeter بازاستخراج کرده‌اند، مگر اینکه آن فرایند واقعاً جداگانه اجرا و
مستند شود.

## ترتیب اجرا

1. سلول ۱: وابستگی‌ها، seedها، مسیرها و تنظیمات مشترک.
2. سلول ۲: توابع پیش‌پردازش، لایه `CausalPropagation`، مدل‌ها و معیارها.
3. سلول ۳: داده مصنوعی، DoWhy، refutation و Random Forest.
4. سلول ۴: آزمایش CIC-DDoS2019 MSSQL.
5. سلول ۵: آزمایش CICFlowMeter Bot-IoT.
6. سلول ۶: تجمیع خروجی‌های نهایی مقاله.

اگر DoWhy نصب نباشد، برای سلول اول Internet را فعال کنید. در صورت تغییر
کتابخانه‌های اصلی توسط pip، Session را Restart و سپس همه سلول‌ها را از ابتدا
اجرا کنید.

## اجرای آزمایشی و اجرای نهایی

برای بررسی سریع pipeline می‌توان در سلول ۱ مقدار `MSSQL_NROWS` را موقتاً یک
عدد کوچک قرار داد. برای تولید نتیجه نهایی مقاله مقدار آن باید `None` باشد و
Notebook از ابتدا اجرا شود. نتیجه اجرای آزمایشی نباید وارد مقاله شود.

## خروجی‌های معتبر

همه خروجی‌ها در مسیر زیر ذخیره می‌شوند:

`/kaggle/working/validated_outputs`

برای اصلاح مقاله فقط از این فایل‌ها استفاده کنید:

- `validated_synthetic_results.csv`
- `validated_all_results.csv`
- فایل‌های `*_metadata.json`
- فایل‌های `*_causal_gradient_importance.csv`
- `environment_versions.json`

مدل‌های آموزش‌دیده و history هر اجرا نیز ذخیره می‌شوند. اعداد قبلی مقاله فقط
پس از تطبیق با این خروجی‌های تازه باید حفظ شوند؛ در صورت اختلاف، خروجی اجرای
پاک و کامل جایگزین عدد قبلی شود.

## معیار تشخیص اجرای معتبر

- تمام سلول‌ها در یک Session تازه و به‌ترتیب اجرا شده باشند.
- هیچ خروجی hard-coded یا سلول recovery در نتایج استفاده نشده باشد.
- انتخاب ویژگی و scaler فقط روی train برازش شده باشند.
- balancing فقط روی train انجام شده باشد و test بازنمونه‌گیری نشده باشد.
- MLP و Causal-MLP دقیقاً از همان split استفاده کنند.
- مدل Causal-MLP شامل لایه `CausalPropagation`، ماتریس `A_X` و مقدار نهایی
  `learned_alpha` باشد.
- مسیر Dataset، نسخه کتابخانه‌ها، seed و نگاشت ویژگی‌ها در metadata ثبت شده
  باشند.
